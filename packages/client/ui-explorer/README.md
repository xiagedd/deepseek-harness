# @deepseek-ai/dsh-client-ui-explorer

English | [中文](README.zh.md)

Workspace file tree for the web conversation details column. The browser half occupies the conversation-declared `conversation.details.explorer` child seat — never the `details` body, which would shadow `DetailsPanel` and hide tool output. A session-header "Files" action opens that details column so the tree is visible without first inspecting a tool call. Explorer and CM6 preview are account-wide capabilities: every workspace Session can open them, and switching Session / workspace leaves the columns open while the tree rebinds to that session's cwd (browse state stays bucketed per cwd).

The tree root is the current session workspace (`cwd`). Folders expand and collapse one `host.listEntries` level at a time. Expanded folder paths and open preview tab paths (path list + active path only) persist in browser `localStorage` under `dsh.explorer.tree.v1`, bucketed by workspace cwd inside one root-scoped store — never through session `scopeKey`, and never as Host settings. A hard reload rehydrates those paths and re-lists / re-reads them; missing paths drop silently. Unsaved preview drafts and dirty flags stay in memory only. `.meta` files are omitted from the listing (Unity sidecars such as `Foo.cs.meta`); directories stay. Empty folders use a distinct glyph and muted hint instead of a fake child row. Folder rows carry three glyph states: a filled folder when the directory holds visible children, an outline folder when it is empty, and an open folder while expanded. A collapsed folder's filled-vs-outline glyph comes from a cached, non-blocking one-level `host.listEntries` probe over the visible unexpanded directories; until that result arrives (or if it fails) the glyph stays filled, so it never flickers. File-type glyphs distinguish folders, C# / code, text, images, JSON/YAML, and other files. The title-row refresh control re-lists only currently expanded directories and drops the probe cache. Reveal expands ancestors and highlights a path that actually exists as a successful in-page preview or a composer `@` workspace-file chip under `cwd`; with no such fact the tree stays unhighlighted. Reveal scrolls to a target only until its row exists, so a later expand or probe never yanks the viewport back to a stale reveal and pushes the just-clicked row out of view. File clicks call `host.readText` and open an editable CodeMirror 6 preview (swappable text-preview engine; Monaco is the planned follow-on) with Save / Ctrl/Cmd+S through `host.writeText`. With the preview editor focused, Ctrl/Cmd+L (and a toolbar or right-click "引用到聊天" entry) inserts a workspace-file chip into the composer — path plus optional line range from the selection, never the selected body — through the same insert path as the tree context menu. Preview appearance (presets, chrome/syntax color overrides, font size, line height, line numbers) lives in Host settings namespace `ui-explorer-preview`, publishes `--dsh-editor-*` through `theme.overrideTokens` → `ThemePresenter`, and is edited from General Settings → 编辑器预览. Bodies over 1 MiB stay out of the editor. There is no `window.open` preview. Double-clicking a code file (`.cs`, `.ts`, `.cpp`, and the rest of the 代码 type filter) is Unity's script gesture: the file goes to the Host OS default application through `host.openPath` — Visual Studio for `.cs` on a Unity workstation — and, when the workspace root lists a solution, that solution follows so the editor loads the project instead of a loose file. The root solution named after the workspace wins, otherwise the first `.sln` in name order. The file is handed over first, because a cold editor then owns one window that the solution request joins. Single click still only opens the in-page preview, a double-clicked folder only expands or collapses, and a handoff failure or a `canOpenPath === false` deployment says so in the tree notice. OS open remains a file context-menu action; "在文件管理器中显示" / Reveal in Finder|File Explorer (platform-local copy) calls `host.revealPath` so the OS file manager opens the parent and selects the item (files and folders alike). Composer workspace-file chips click through the optional `workspaceReveal` service to expand, highlight, open the preview tab, and — when the chip carries a `:start-end` suffix — scroll and select that line range in CodeMirror. Ctrl/Cmd and Shift select a set; copy/cut/paste go through `host.copy` and `host.rename`. Dragging a file or folder onto another folder is the same move as cut-and-paste (`host.rename`): drops onto the dragged item or its descendants are refused, Host errors surface as-is, and only related expanded layers refresh. This package does not occupy the `details` body and does not show Git badges.

Non-empty search queries call `host.searchEntries` and cover the tree with fuzzy-ranked matches from the whole workspace. Results are an overlay, not a replacement: the tree stays mounted underneath, so clearing the query (Escape or an empty box) returns the same expanded folders, selection, and scroll offset the search interrupted, and a search never writes an empty expansion list to `dsh.explorer.tree.v1`. Activating a result is a deliberate move rather than a reset — a directory clears the query and reveals itself, a file opens its preview tab, and both expand the ancestors they need. Host enumeration applies `.gitignore` plus `.dshignore` (preferred) or `.cursorignore`, including `*`, `**`, root-relative paths, directory rules, comments, and `!` negation; ignored directories are pruned before descent, so the tree, search results, and `@` workspace-file candidates agree. Refresh re-reads ignore files, while search re-reads them on every request.

Hidden entries from the Host listing are omitted. An empty workspace, an empty folder, a listing failure, and a deployment with `canOpenPath === false` each have copy; the last of those still allows the in-page preview.

## Model Experience

None, as this package renders a Host filesystem listing for a human and touches no prompt, message, schema, stream, or tool result.

#### KV Cache effect

None; the package never assembles or sends provider requests.

## Known Limitations and Deferred Work

- **Git badges** — later explorer work, and only if a Host Git-status RPC exists.
- **Monaco / VS Code–like editor** — preview editing uses CodeMirror 6 behind `TextPreviewEngineProps`; Monaco is a later engine swap, not a v1 dependency.
- **Large-file windowing** — bodies over 1 MiB are refused in the preview column; ranged reads are not implemented.
- **Emptiness probe cost** — the filled-vs-outline folder glyph runs one background `host.listEntries` per visible collapsed directory (cached until refresh or a mutation); a dedicated Host `hasChildren`/`childCount` field would remove those probe calls.
